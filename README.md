# Balance — офлайн PWA

Демонстрационный расчёт массы и центровки HS-125-800XP **RA-02734 / SN 258719**, по предоставленной фотографии. Все расчёты и сохранение выполняются на устройстве. Серверная логика, аккаунты и внешние ресурсы не нужны.

## Запуск

На этом Mac достаточно выполнить из папки проекта (скрипт найдёт встроенный Node.js Codex):

```sh
./start.sh
```

При обычной установке Node.js 20 или новее также работает команда ниже. Установка пакетов не требуется:

```sh
npm start
```

Откройте `http://localhost:4173`. Альтернатива: `node scripts/serve.mjs`. Порт задаётся переменной `PORT`. Локальный сервер раздаёт только каталог `dist/`.

Для размещения скопируйте **содержимое `dist/`** на любой статический HTTPS-хостинг. Приложение поддерживает размещение в подкаталоге. `file://` не поддерживает Service Worker.

## Ручная публикация на GitHub Pages

Репозиторий: [GVA777777/weight-balance](https://github.com/GVA777777/weight-balance). Ожидаемый адрес после первого успешного выпуска: **https://gva777777.github.io/weight-balance/**. Фактический адрес появится в окружении `github-pages` и сводке workflow.

Публикация запускается **только вручную**. Push в `main` и pull request сами по себе не выпускают сайт. Workflow разрешает выпуск только из `main`.

### Первоначальная настройка

1. Закоммитьте подготовленные изменения и отправьте их в `main` репозитория.
2. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Если Pages недоступен, проверьте тариф и права: на GitHub Free доступен Pages для публичных репозиториев; для приватных нужен подходящий платный тариф. Видимость репозитория этот проект не меняет.
3. Откройте **Actions → Deploy GitHub Pages → Run workflow**, выберите ветку **main** и нажмите **Run workflow**.
4. Дождитесь успешного выполнения `Check and prepare static site` и `Publish to GitHub Pages`. Откройте адрес из окружения `github-pages` или раздела **Published GitHub Pages site** в сводке запуска.

При необходимости ограничьте окружение **Settings → Environments → github-pages** веткой `main`; сам workflow уже проверяет ветку. Персональные токены, secrets, ветка `gh-pages` и установка npm-пакетов не нужны. Настройка следует [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Если кнопки **Run workflow** нет, убедитесь, что файл workflow уже находится в `main`, GitHub Actions разрешён для репозитория и у вас есть права запуска. Если настройка/публикация сообщает об отключённом Pages, сначала выполните шаг 2. При ошибке тестов опубликованный сайт не заменяется.

### Подготовка файлов и последующие выпуски

Workflow использует Node.js 24 и выполняет:

```sh
npm test
npm run check
npm run build:pages
```

Команда `build:pages` создаёт **`artifacts/pages/`** из содержимого `dist/`. В GitHub Pages отправляется только этот каталог: `index.html` располагается в корне публикации, а не по дополнительному пути `/dist/`. README, тесты, исходная фотография и локальные настройки в артефакт не попадают. Символические ссылки в публикуемых ресурсах не допускаются.

Версия кеша в подготовленном `sw.js` автоматически получает SHA-256 имён и содержимого файлов приложения. При изменении любого ресурса создаётся новая версия, при повторной сборке тех же файлов — та же версия. Исходные файлы `dist/` не изменяются. Поэтому при публикации через этот workflow не нужно вручную повышать версию `CACHE`.

Для следующего выпуска отправьте изменения в `main` и снова запустите **Run workflow**. Публикации выполняются последовательно. Обновления на устройстве загружаются при подключении к интернету; после установки обновления Service Worker перезагрузите приложение. Сохранённый расчёт не удаляется при обновлении кеша.

### Проверка первого выпуска

1. Откройте опубликованный HTTPS-адрес и дождитесь надписи **«Офлайн готов»**.
2. Введите тестовый расчёт, включая общий остаток топлива. При желании установите PWA на главный экран.
3. Отключите интернет и повторно откройте или перезагрузите приложение по тому же адресу.
4. Убедитесь, что значения сохранились; измените загрузку и проверьте перерасчёт взлёта и посадки.
5. Откройте **Предпросмотр** и проверьте печатный лист; в обычном браузере проверьте **Печать / PDF**, A4, масштаб 100%, без колонтитулов.

Первое открытие на каждом устройстве требует интернета. Очистка данных сайта удаляет локальный расчёт и офлайн-копию. Сохранения с `localhost` на домен GitHub Pages автоматически не переносятся. Данные рейса приложение не отправляет на GitHub. Сайт Pages обычно публичный, в том числе при приватном исходном репозитории; доступность и ограничения зависят от тарифа GitHub.

## Работа

- Первый запуск открывает пример с фотографии. На посадке исходно нет значения: введите общий остаток топлива.
- Переключатель кг/lbs меняет ввод и отображение; сохранённые веса и расчёты остаются в lbs. Ввод допускает десятичную запятую.
- Сначала вырабатывается подфюзеляжный бак, затем крыльевые. Остатки и расход по бакам вычисляются из общего остатка.
- Пустое поле остатка отличается от введённого нуля. Неверные значения блокируют зависимые результаты и печать; превышения ограничений показываются отдельно и печатаются.
- Данные автоматически сохраняются в localStorage текущего браузера. Новый расчёт и восстановление примера заменяют текущий расчёт после подтверждения.
- «Предпросмотр» показывает лист A4. «Печать листа» открывает системный диалог; выберите A4, масштаб 100%, отключите колонтитулы браузера. Можно сохранить PDF. Печать всегда в lbs/ft.
- После появления «Офлайн готов» закройте приложение, отключите сеть и откройте его снова. Форма, графики и печать доступны без сети. На поддерживаемых браузерах появится «Установить»; на iOS используйте Safari → Поделиться → На экран «Домой».
- Профиль браузера и его кеш должны сохраняться: очистка данных сайта удалит расчёт и офлайн-копию.

## Ограничения демо

Не использовать для выполнения полётов. Снаряжённая масса 16 321 lbs, плечо 0,513 ft и плечи загрузочных позиций перенесены из фото; актуальность исходного весового состояния не подтверждена.

Плечи топлива **постоянные: 0,69 ft и 8,36 ft**. В реальном самолёте зависимость может быть иной; кривую из фото показываем только как приближённую справочную иллюстрацию. Максимальный запас крыла 8 446 lbs взят из печатной подписи графика; 7 799 lbs — из рукописного примера. Весовые ограничения: без топлива 18 450 lbs, взлёт 28 000 lbs, посадка 23 350 lbs; багаж 250 / 100 / 45 lbs.

Шкала САХ приблизительная: линейная демонстрационная калибровка относительно точки 0,513 ft / 24,8%, длина условной САХ 6,8 ft. Это **не подтверждённая геометрия самолёта**. Контур центровки приблизительно перерисован по фото; приложение не проверяет эксплуатационный допуск по этому контуру. Печатный бланк повторяет структуру и расположение исходного; это чистая векторная реконструкция фотографии, а не скан оригинального документа.

## Проверки и архитектура

```sh
npm test
npm run check
```

- `dist/src/profiles.js`: модель, борт, места, плечи, ограничения, пример и реестр профилей. Все размеры — lbs/ft.
- `dist/src/calculate.js`: чистые функции расчёта, конвертация, валидация и порядок выработки топлива; JSDoc-типы `AircraftModel`, `AirframeProfile`, `FlightInput`, `CalculationResult`.
- `dist/src/app.js`: интерфейс и состояние; `storage.js`: проверка сохранённого состояния; `graphics.js`: SVG; `print.js`: печатный шаблон.
- `dist/sw.js`: кеш всего приложения. Для GitHub Pages версия `CACHE` вычисляется автоматически командой `build:pages`; при прямом размещении исходного `dist/` или локальном предпросмотре после изменения ресурсов повышайте её вручную. Обновление устанавливается только после полного кеширования всех ресурсов.
- `scripts/prepare-pages.mjs`: подготовка отдельного артефакта публикации и SHA-256 версии кеша, без изменения `dist/`.
- `tests/`: контрольные числа фотографии, выработка баков, посадочные итоги, единицы, ограничения, некорректный ввод, сохранение, экранирование и офлайн-оболочка.

Для следующей модели добавьте отдельный `AircraftModel` и `AirframeProfile` в реестр, затем подключите выбор профиля и соответствующую топливную модель. Текущий экран намеренно поддерживает только первый борт; профиль и расчётный модуль уже разделены.
